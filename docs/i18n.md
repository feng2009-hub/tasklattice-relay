# Control console internationalization

The Control console uses `i18next` with `react-i18next`. Translation resources
are grouped by feature namespace in
`apps/control/src/i18n/resources.ts` and are type-checked through the i18next
module augmentation in `apps/control/src/i18n/i18next.d.ts`.

The currently supported languages are English (`en-US`), Simplified Chinese
(`zh-CN`), and Traditional Chinese (`zh-TW`). Traditional Chinese browser tags
such as `zh-Hant`, `zh-HK`, and `zh-MO` resolve to `zh-TW`.

## Language resolution

The server resolves the initial language for every request in this order:

1. `tali.account.language` cookie
2. `Accept-Language` header
3. `en-US`

The account preference is mirrored to the cookie when the profile loads or the
user changes language. The client initializes from the server-rendered
`<html lang>` value so hydration uses the same language as SSR. Each Router
instance owns its own i18next instance; server requests never mutate a shared
language instance.

## Using translations

Feature components should use their namespace directly:

```tsx
const { t } = useTranslation("createInstance");

return <CardTitle>{t("defineAgent.title")}</CardTitle>;
```

Shared UI primitives should continue to receive visible labels through props.
Do not put business-specific translations inside Button, Card, Dialog, or other
design-system primitives.

Components must read translations from `useTranslation()` directly. Do not add
language props, feature-specific message objects, fixed global translators, or
compatibility hooks around react-i18next. Pure helpers that need localized text
should receive a typed `TFunction` from their calling component.

Long-form localized documents may stay in language-specific Markdown files.
Their navigation labels and other UI copy still belong in an i18next namespace;
only the document bodies are selected by locale.

Use interpolation instead of concatenating translated fragments:

```tsx
t("account.openMenu", { displayName });
```

## Adding a namespace or language

1. Add the same key structure for every supported language in `resources.ts`.
2. Add a new namespace to the `ns` list in `create-i18n.ts`.
3. Use `useTranslation(namespace)` in React components.
4. Add tests for the new language, interpolation, plurals, or fallback behavior.
5. Verify SSR, client switching, mobile layout, and the production build.

API responses should expose stable error codes and parameters rather than
language-specific messages when the client is expected to translate the error.
Server-generated user content such as email can translate with a request- or
recipient-scoped i18next instance.
