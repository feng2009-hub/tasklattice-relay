# 專案管理員指南

建立專案邊界、設定團隊，並對資源、執行階段、原則與證據負責。

## 建立專案

1. **確認身分與專案範圍。** 執行任何管理操作前，先確認專案切換器中的目前專案。專案名稱與 ID 是持久的資源歸屬邊界，不只是顯示名稱。[開啟專案概覽](/__project__)。
2. **邀請成員並指派最低必要角色。** 在專案設定中將成員指派為管理員、開發人員、核准者、稽核員或一般使用者。務必保留至少一位管理員，並定期移除已失效的成員。[開啟專案設定](/__project__/setting)。
3. **連接模型並設定路由。** 註冊模型提供者、驗證模型、選擇預設路由，並在正式使用前設定專案預算。[開啟模型與路由](/__project__/setting)。

## 支援 Agent 安全交付

- **管理能力資源。** 先發布已核准的技能、MCP 連線與知識來源，再允許開發人員將它們繫結至 Agent。[開啟技能](/__project__/skills)。
- **定義存取與執行階段原則。** 使用存取原則控制工具與資料邊界，並以執行階段原則定義執行環境。建立執行個體前，請檢查最後生效的原則。[開啟存取原則](/__project__/access-policies)。
- **檢查執行階段狀態。** READY 必須代表已觀測到的健康狀態。將新的執行個體指派給使用者前，請先檢查建立日誌與健康訊號。[開啟執行個體](/__project__/instances)。

## 依據證據維運

- **監控用量、成本與配額。** 對照專案預算檢查費用與活動。缺少用量歸屬資訊不代表風險為零。[開啟成本](/__project__/cost)。
- **審查決策與活動。** 使用追蹤記錄查看執行行為，使用稽核日誌查看管理操作、授權決策與保留的中繼資料。[開啟稽核日誌](/__project__/audit-logs)。
- **謹慎處理破壞性變更。** 刪除專案或執行個體會影響隔離資源。請先評估影響、保留必要證據，並溝通復原計畫。[開啟專案設定](/__project__/setting)。

> **管理員是承擔責任的角色。** 這不是繞過服務核准流程的捷徑。日常工作應採用最低必要的人員角色，並確保管理活動可供稽核。
