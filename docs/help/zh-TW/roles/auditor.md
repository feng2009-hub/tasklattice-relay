# 稽核員指南

在不修改受檢系統的前提下，審查專案行為、授權、執行階段、用量與保留的證據。

## 執行證據審查

1. **定義範圍與時間區段。** 明確列出專案、審查目標、相關人員、資源與有限的時間範圍。儲存使用的篩選條件，以便日後重現。[開啟稽核日誌](/__project__/audit-logs)。
2. **追蹤管理與授權活動。** 依操作人員、動作、物件類型與結果篩選，區分遭拒絕的嘗試、失敗操作與成功變更。[開啟稽核篩選](/__project__/audit-logs)。
3. **關聯執行證據。** 結合追蹤、執行階段日誌、設定、用量與成本，判斷實際行為是否符合宣告的邊界。[開啟追蹤記錄](/__project__/traces)。
4. **謹慎匯出與報告。** 記錄查詢條件、時區、匯出時間、資料缺口與完整性結果。敏感欄位缺失或經過遮罩處理，都是必須明確註記的證據限制。[開啟稽核匯出](/__project__/audit-logs)。

## 唯讀檢查區域

- **資源與原則。** 以唯讀方式檢查 Agent 設定、技能、MCP 工具、知識來源、存取原則、執行階段原則、模型與路由。[開啟存取原則](/__project__/access-policies)。
- **用量與成本。** 除了總量，也要檢查歸屬與資料品質訊號。結論中必須保留不完整的歸屬鏈路。[開啟成本](/__project__/cost)。

> **敏感內容仍受邊界控制。** 稽核權限不會自動顯示金鑰、原始憑證或所有敏感承載內容。應將遮罩情況寫入證據邊界，而不是嘗試繞過限制。
