# 项目管理员指南

建立项目边界、配置团队，并对资源、运行时、策略和证据负责。

## 建立项目

1. **确认身份与项目范围。** 执行任何管理操作前先确认项目切换器中的当前项目。项目名称和 ID 是持久的资源归属边界，不只是显示名称。[打开项目概览](/__project__)。
2. **邀请成员并分配最小必要角色。** 在项目设置中将成员分配为管理员、开发者、审批者、审计员或普通用户。始终保留至少一名管理员，并定期清理失效成员。[打开项目设置](/__project__/setting)。
3. **连接模型并设置路由。** 注册模型提供商、验证模型、选择默认路由，并在生产使用前设置项目预算。[打开模型与路由](/__project__/setting)。

## 支持智能体安全交付

- **管理能力资源。** 先发布经过批准的技能、MCP 连接和知识源，再允许开发者将它们绑定到智能体。[打开技能](/__project__/skills)。
- **定义访问与运行时策略。** 使用访问策略控制工具和数据边界，使用运行时策略定义执行环境。创建实例前检查最终生效策略。[打开访问策略](/__project__/access-policies)。
- **检查运行时状态。** READY 必须代表已经观测到的健康状态。将新实例分配给用户前，先检查创建日志和健康信号。[打开运行时实例](/__project__/instances)。

## 基于证据运营

- **监控用量、成本与配额。** 对照项目预算检查费用和活动。用量归因缺失不等于风险为零。[打开成本](/__project__/cost)。
- **审查决定与活动。** 使用追踪记录查看执行行为，使用审计日志查看管理操作、授权决定和保留元数据。[打开审计日志](/__project__/audit-logs)。
- **谨慎处理破坏性变更。** 删除项目或实例会影响隔离资源。先评估影响、保留所需证据并沟通恢复计划。[打开项目设置](/__project__/setting)。

> **管理员是承担责任的角色。** 它不是绕过服务审批执行的捷径。日常工作应使用最小必要的人类角色，并确保管理活动可审计。
