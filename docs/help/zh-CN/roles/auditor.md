# 审计员指南

在不修改被检查系统的前提下，审查项目行为、授权、运行时、用量和保留证据。

## 执行证据审查

1. **定义范围与时间段。** 明确项目、审查目标、相关人员、资源和有限时间范围。保存所用筛选条件以便复现。[打开审计日志](/__project__/audit-logs)。
2. **跟踪管理与授权活动。** 按操作人、动作、对象类型和结果筛选，区分被拒绝的尝试、失败操作和成功变更。[打开审计筛选](/__project__/audit-logs)。
3. **关联执行证据。** 结合追踪、运行时日志、配置、用量和成本，判断实际行为是否符合声明的边界。[打开追踪记录](/__project__/traces)。
4. **谨慎导出与报告。** 记录查询条件、时区、导出时间、数据缺口和完整性结果。敏感字段缺失或脱敏属于明确的证据限制。[打开审计导出](/__project__/audit-logs)。

## 只读检查区域

- **资源与策略。** 只读检查智能体配置、技能、MCP 工具、知识源、访问策略、运行时策略、模型和路由。[打开访问策略](/__project__/access-policies)。
- **用量与成本。** 除了总量，还要检查归因与数据质量信号。结论中必须保留不完整的归因链路。[打开成本](/__project__/cost)。

> **敏感内容仍受边界控制。** 审计权限不会自动展示密钥、原始凭证或所有敏感载荷。应将脱敏情况写入证据边界，而不是尝试绕过它。
