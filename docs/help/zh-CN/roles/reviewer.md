# 审批者指南

独立审查受治理的变更，核对请求范围，并始终区分审批决定与实际执行。

## 审查请求

1. **确认请求人与目标。** 确认谁提出了变更、影响哪个项目资源，并确保自己独立于请求人和目标操作员。[打开请求预览](/__project__/requests)。
2. **评估证据。** 比较业务理由、请求限制、策略影响、风险、可恢复性以及能够满足需求的最小范围。
3. **记录有边界的决定。** 说明理由后批准、拒绝或要求修改。审批决定不能暗示变更已经实际应用。
4. **单独验证执行结果。** 经批准的变更由责任服务或操作员执行后，再通过保留证据确认实际结果。[打开审计日志](/__project__/audit-logs)。

> **审批工作区目前是预览功能。** 角色与能力模型已经存在，但请求界面尚未连接持久化的决策和执行 API。预览操作不是正式审批，也不会应用任何变更。
